# checkout-demo Trace 健康基线：2026-08-22

> 范围：单服务 `/checkout` 的最小 Trace 链路。本文保存脱敏的验证结论与对象状态，不提交原始 Trace payload、完整 Trace ID、请求 body、Header 或任何凭据。

## 1. 验证目标

```text
checkout-demo /checkout (200)
→ W3C traceparent 继续传播
→ OTLP/HTTP
→ otel-collector（memory_limiter + batch）
→ Tempo（单副本、本地 24h retention）
→ Grafana Tempo datasource / Loki trace_id 回查
```

这证明最小深度证据链可用；不证明跨服务追踪、生产采样、HA、租户隔离或根因。

## 4. 属性与数据边界

应用 Span 的固定属性白名单：

```text
http.request.method
url.path
http.response.status_code
```

Resource：`service.name`、`deployment.environment`、`service.version`、`k8s.namespace.name`、`k8s.cluster.name`。

禁止入 Span：request/response body、完整 query、Cookie、Authorization、token、user_id、request_id、SQL 参数。`request_id` 只留在应用日志，Trace 与日志用 `trace_id` / `span_id` 关联。

## 5. 结论级别

- **已观察事实：**健康 checkout 请求确实产生、被 Collector 接收、被 Tempo 导出/查询，并能在 Loki 以 Trace ID 回查日志。
- **时间相关：**同一受控请求的 HTTP、Trace、日志出现在对应调查时间窗内。
- **已证实机制：**本 Lab 的手工 SDK + W3C propagation + OTLP HTTP + Collector + Tempo 配置能够传输单服务健康请求 Trace。
- **未证明：**多服务 context、真实生产延迟/故障根因、采样成本、Collector/Tempo HA、跨集群、隔离与灾备。
