# checkout → inventory 跨服务 Trace 与下游故障恢复

- 日期：2026-08-22；范围：单集群、单服务依赖 Trace Lab。
- 脱敏：不保存原始 Trace ID、request ID、body、Header 或凭据。

## 已验证

1. 提交 `8b5a19c` 新增最小 `inventory-demo`（1 副本、ClusterIP、非 root、只读文件系统、无 SA token/RBAC），checkout 以 W3C `traceparent` 调用 `/reserve`。
2. 健康请求的同一 Trace 中有 `checkout-demo / GET /checkout` 与其子 Span `inventory-demo / GET /reserve`；两服务 Loki 日志均可由同一 trace_id 回查，事件分别为 `checkout_succeeded`、`inventory_reserved`。
3. 受控故障提交 `e31cd95` 仅将 inventory `LAB_MODE=unhealthy`、revision 改为 incident。Argo 对齐该 revision；两个 Deployment 仍 Available，inventory `/healthz` 仍 200，但 checkout 请求为 503。
4. 故障 Trace 显示：checkout 503 / `inventory_dependency_failed`；inventory 503 / `lab_mode_not_healthy`。Loki 对应 `checkout_dependency_failed` 与 `inventory_reserve_failed`。
5. Synthetic Probe 为 0；critical firing，warning firing 但被 Alertmanager inhibition suppress；Collector 持续接收/导出，未观察 exporter failure 样本。
6. `git revert e31cd95` 产生 `77bca83`。Argo Synced/Healthy 对齐；inventory 回到 healthy/baseline；新 checkout 请求 200、新 Trace 和两边成功日志可查询；Probe=1；Checkout firing alerts=0。

## 边界

这证明最小上游/下游证据关联和回滚，不证明生产根因、采样、HA、多租户、对象存储或跨集群能力。
